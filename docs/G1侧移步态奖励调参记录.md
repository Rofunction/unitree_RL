## 0. 方法论：先测量，单变量，数字验收

这一轮所有改动都遵循同一流程，避免"凭感觉调参"：

1. **现象 → 数字**：先扩展 `measure_feet.py` 加一个能量化该现象的指标；
2. **根因**：读奖励公式找出"策略为什么理性地做出错误动作"（策略总是精确跟踪奖励目标，
   所以**目标本身错了**比"罚得不够重"更常见）；
3. **单变量改动**：一次只改一个奖励的形状或 scale，其余冻结；
4. **续训**：`--resume` 从上一 ckpt 接着训（注意 rsl_rl 的 `max_iterations` 是**增量**）；
5. **复测验收**：重跑测量脚本，对照事先写好的数字标准。

测量命令（固定 vy=-0.5，50 env，无噪声无推力）：

```bash
python legged_gym/scripts/measure_feet.py --task=g1 --headless \
    --load_run=<run名> --checkpoint=<ckpt> --vel=-0.5
```

## 1. 底座：相位步态先验（非本轮改动，但所有公式依赖它）

```python
period  = 0.65                    # 步态周期 0.8→0.65s：提高步频、降低每步横移量、抑制垫步
offset  = 0.5                     # 左右脚反相
phase   = (t % period) / period
leg_phase[左] = phase
leg_phase[右] = (phase + 0.5) % 1
支撑期: leg_phase < 0.55          # 占空比 0.55
摆动窗: 0.45 × 0.65s = 0.293s     # 实测摆动时长中位 0.300s，吻合
```

- 观测里加了 `sin(2πφ), cos(2πφ)`（obs 47 维的最后 2 维），策略知道自己在周期哪里；
- `_reward_contact`（scale 0.18）：`~(接触 XOR 相位支撑期)`，把落脚时刻焊在相位上。
  实测离地滞后相对相位 0.55 仅 **+0.012 相位 ≈ 7ms**，说明相位锚定非常牢。

** dof 顺序备忘 **（URDF 每腿 pitch,roll,yaw,knee,ankle_p,ankle_r）：
hip_pitch=[0,6]，hip_roll=[1,7]，**hip_yaw=[2,8]**，脚=ankle_roll link。

## 2. 问题一：内八（双脚朝内撇）

**现象**：侧移时脚尖明显内扣。
**根因**：内八本质是 hip_yaw 内旋。早期 hip_pos 罚项覆盖了全部 hip 关节，
其中 [0,6]=hip_pitch 被罚会**压制抬腿**（抬腿靠 pitch），是误伤。
另：周末版本曾在 default_joint_angles 里给 hip_roll 加 0.06 外展先验，已撤回——
内八是 yaw 现象，roll 默认角治不了，还只是个软先验。

**改动**（`_reward_hip_pos`，scale −4.0）：

```python
return torch.sum(torch.square(self.dof_pos[:, [2, 8]]), dim=1)   # 只罚 hip_yaw
```

**结果**：内八消失，且不再拖累抬腿（为后面抬腿速度的修复扫清障碍）。

## 3. 问题二：交叉腿 / 两腿间距过近

三个奖励配合，编号沿用代码注释里的 ②④⑤：

### ② feet_lateral_align（scale 0.5，正奖励）

```python
return Σ (feet_vy × cmd_vy × swing)      # swing = ~contact
```

摆动脚朝指令方向移动给正分 → 抑制"错腿先抬"和交叉迈步的趋势。

### ④ feet_collision（scale −1.0）

```python
return Σ (接触力>1N × 1[leg_phase ≥ 0.55])
```

堵"脚-脚接触零成本"的洞：相位规定的摆动窗内脚上出现接触力 = 刮蹭另一条腿/没抬起。

### ⑤ feet_clearance v3（scale −8.0）——从线性改平方尖峰

两脚在**躯干系水平面**的 2D 距离 dist（含 x 分量，允许剪刀式错开绕行），只门控摆动脚：

```python
too_close = (clamp(0.12 − dist, 0) / 0.12)²
```

**判断依据（罚多大才够）**：dist=0.06 处 v3 罚 −2.0/步，旧线性只有 −0.24/步，
差近 10 倍——线性版策略选择硬吃罚分。平方尖峰 dist≥0.12 时严格零拖累，
不污染已达标的步态。

**阈值 0.12 的几何依据**：物理碰撞临界 ≈0.07m；双脚站姿宽 0.218m、髋横向扫程 0.18m，
纯横向保持 0.18 不可达 → 目标定为"安全余量"而非"理想间距"。

**结果**：用户确认侧移时两腿距离合理。本轮终点复测（ckpt 30000）：
2D 距离 1% 分位 0.101m、中位 0.192m，站姿宽 0.247m。

## 4. 问题三：抬腿慢、抬不高

**现象**：侧移抬腿速度慢、高度低。
**测量**（当时 ckpt）：抬脚量（空中脚 z 中位 − 支撑脚 z 中位）仅 **0.051m**，峰值 0.095m。

**根因（本轮最关键的发现）**：`feet_swing_height` 的目标 0.10m 是四足模板
（a1 的脚 link 高 ≈0.02m）搬过来的**绝对高度**；而 G1 的脚 = ankle_roll link，
**支撑期其原点 z = 0.035m**。目标 0.10 绝对高度 ⇒ 真实离地间隙只有 0.065，
策略精确跟踪（峰值 0.095 ≈ 目标 0.10）——"策略没错，是奖励目标错了"。

### v4：目标 0.10 → 0.13（绝对）

```
0.13 = 支撑高 0.035 + 期望离地间隙 0.095
```

**结果**（ckpt 26000）：抬脚量 0.051→**0.073m**，峰值 0.124，vy 跟踪 −0.395→−0.464。
抬腿速度问题解决——**但引入新问题**（见下）。

## 5. 问题四：空中停顿（顶点悬停后砸下）

**现象**：抬腿快了，但脚在最高点明显停顿约 0.1~0.2s 再落下。
**测量**（ckpt 26000）：**顶点平台时长（峰值−1cm 内）中位 0.120s**，75% 分位 0.140s，
而整个摆动窗才 0.300s；下降耗时 0.140s。

**根因**：v4 是**恒定目标**的二次罚 `(z−0.13)²`。它在顶点附近梯度极小——
**趴在顶点悬停是零成本最优解**；提前下降的每一厘米每步都倒扣罚分。
策略理性地选择"抬到 0.13 → 悬停到窗口末 → 掉下来"。

### v5：恒定目标 → 相位正弦包络（最终版）

```python
s     = clamp((leg_phase − 0.55) / 0.45, 0, 1)     # 摆动窗内进度 0→1
z_ref = 0.13 × sin(π·s)                            # 前段逼快抬，后段压落，末段压落地
pos_error = (z − z_ref)² × ~contact                # 支撑脚不受影响（s=0 → z_ref=0，且被门控）
```

**经济学**：悬停在 0.13 的成本随 s 递增——s=0.75 时 z_ref=0.092，罚 ≈−0.03/步；
s=0.9 时 z_ref=0.040，罚 ≈−0.16/步。跟着包络下降是免费的，悬停越来越贵。
z_ref→0 还顺带加了"别晚落地"的压力。

### v5 验收（run Aug19_09-44-54_，ckpt 30000）

| 指标 | v4 (26000) | v5 (30000) | 说明 |
|---|---|---|---|
| vy 跟踪 | −0.464 | **−0.481** / −0.5 | 96%，历史最好 |
| 峰值高度 | 0.124 | 0.104 | 见下方"代价" |
| 峰值时刻占摆动比 | — | **0.43** | 贴近正弦顶点 0.5 |
| 顶点平台时长中位 | 0.120s | 0.100s | 见下方"指标饱和" |
| 抬脚量（中位口径） | 0.073 | 0.049 | 正弦均值 2/π·0.13≈0.083 绝对高，吻合 |
| 2D 距离 1% / 中位 | 0.103 | 0.101 / 0.192 | 回归守门 ≥0.10 通过 |
| 离地滞后 | ~8ms | 7ms | 相位锚定不受影响 |

两个需要正确解读的数字：

- **平台 0.100s ≠ 还有 0.1s 停顿**。正弦顶部天然平缓：完美跟踪者在"峰值−1cm"带内
  就要待 s∈[0.37,0.63] ≈ **0.076s**（指标饱和值）。0.100 − 0.076 ≈ 0.02s 才是真残余，
  视觉上"抬→停→砸"已变成连续圆弧（用户确认可接受）。
- **峰值降到 0.104 是代价**：包络只在瞬间 s=0.5 要求 0.13，二次罚在顶部平坦，
  加上 dof_acc/action_rate 的经济性压力，策略欠冲约 20%。峰值离地间隙仍有
  0.104−0.035 ≈ 0.07m，够过障碍；要更高需抬包络幅值或加大 scale。

## 8. 残留问题与预留旋钮

1. **峰值欠冲**（0.104 < 包络顶 0.13）：要更高离地间隙 → 抬幅值或 scale −20→−40；
2. **更利落的落脚**：包络斜化 `sin(π·s^1.3)`，峰值后移、下降段压缩进 0.1s；
3. **2D 1% 分位 0.101 贴着守门线 0.10**：长尾仍有进尖峰区的瞬间，若恶化先加
   feet_clearance 压力而不是动阈值；
4. **步频**：period 0.65→0.60 作为独立实验（会同时改变摆动窗 0.293→0.27s，
   所有相位相关公式按比例受影响）；
5. **turn_arc ③**（代码里注释保留）：转弯外脚多走、内脚当轴，启用需取消注释 +
   config 加 `turn_arc = 0.2`。

## 9. 测量指标定义（measure_feet.py）

- **抬脚量** = 空中脚 z 中位 − 支撑脚 z 中位（支撑脚 z 中位 ≈ 0.035 = ankle_roll 原点高）；
- **摆动事件** = 连续空中 ≥8 帧（0.16s）的一段，只统计 warmup 后；
- **顶点平台时长** = 事件内 z ≥ 峰值−0.01 的帧数 × dt；
  **注意正弦步态下指标饱和于 ~0.076s**，不是零才是好；
- **离地滞后** = 事件起点相位 − 0.55（折算 ms ×0.65）；
- **2D 距离** = 两脚位置转到躯干系后水平面欧氏距离（含 x）。
